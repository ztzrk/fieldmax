Latar Belakang Permasalahan

Tantangan pengelolaan operasional lapangan olahraga konvensional di Kota Makassar
1

Pencatatan Reservasi Masih Manual

Penggunaan WhatsApp dan Google Form sering menimbulkan jadwal ganda (double booking) dan human error.

2

Verifikasi Pembayaran Terpisah

Bukti transfer disahkan manual satu per satu, memperlambat konfirmasi sewa dan berisiko bukti pembayaran palsu.

3

Sulit Cek Ketersediaan Real-Time

Pelanggan (User) kesulitan melihat slot jam yang pasti secara fleksibel tanpa harus menghubungi pengelola.

4

Tidak Ada Dasbor Rekapitulasi Renter

Pemilik lapangan (Renter) kesulitan memantau tren omzet pendapatan dan laporan transaksi secara otomatis.

3

Rumusan Masalah

1

Bagaimana merancang dan membangun sistem informasi penyewaan lapangan olahraga berbasis web yang dapat menggantikan pencatatan manual?

2

Bagaimana mengatasi masalah jadwal yang konflik (double booking) dan ketidakpastian ketersediaan lapangan secara real-time?

3

Bagaimana menyediakan platform terintegrasi yang memudahkan pengelola (Renter) dalam manajemen data transaksi dan laporan pendapatan, serta memudahkan pelanggan (User) dalam pencarian dan pemesanan?

4

Tujuan Penelitian

01

Digitalisasi Sistem

Merancang & membangun platform web yang menggantikan peran buku agenda dan pesan manual dengan basis data digital yang terstruktur.

02

Pencegahan Schedule Conflict

Menyediakan fitur pengecekan jadwal ketersediaan real-time untuk menjamin tidak ada dua booking pada jam dan lapangan yang sama.

03

Platform Terpadu Multi-Tenant

Menghasilkan FieldMax yang memfasilitasi 3 aktor (User, Renter, Admin) dalam reservasi, pembayaran otomatis, dan analitik pendapatan.

5

Batasan & Manfaat Penelitian

Batasan Masalah

  • Sistem dibangun berbasis Web (Responsive Next.js & Express.js) tanpa aplikasi native (Android/iOS).
  • Sistem manajemen basis data menggunakan PostgreSQL.
  • Pengelolaan keuangan dibatasi pada rekapitulasi laporan pendapatan transaksi penyewaan fasilitas (bukan akuntansi mendalam).

Manfaat Penelitian

  • Tersedianya platform terintegrasi otomatis untuk reservasi, pembayaran digital Midtrans, dan kelola venue.
  • Meningkatkan efisiensi waktu, mencegah kerugian double booking, dan memudahkan pemesanan lapangan bagi masyarakat.

Arsitektur Monorepo & Tech Stack

Struktur Full-Stack TypeScript Monorepo (pnpm + Turborepo)

Arsitektur Monorepo

Frontend: Next.js 16 (App Router), React 19, Tailwind CSS v4, shadcn/ui.

Backend: Express.js 5 REST API (Controller → Service → Route pattern).

Shared Package: @fieldmax/shared (Validasi Zod & API Types).

Database: PostgreSQL disetel melalui Prisma ORM v6.

Autentikasi: Session-based auth (sessionId HttpOnly cookie di DB).

Integrasi Layanan Pihak Ketiga

Payment Gateway: Midtrans Snap (Virtual Account, QRIS, GoPay) via Webhook Notification Server.

CDN Upload: ImageKit SDK untuk unggahan foto venue & lapangan.

Layanan Email: Nodemailer (SMTP) untuk kode verifikasi OTP & Reset Password.

Background Cron: Hourly Job otomatis mengubah status CONFIRMED menjadi COMPLETED.

Activity Diagram Process Flow

Alur kerja sistem reservasi real-time dan konfirmasi otomatis

Alur Reservasi User & Midtrans

  1. User memilih venue, tanggal, dan rentang jam sewa.
  2. Sistem memvalidasi ketersediaan jam (menghindari jadwal bentrok).
  3. Sistem membuat catatan Booking (PENDING) dan meminta snap_token dari Midtrans API.
  4. User menyelesaikan tagihan di portal Midtrans Snap.
  5. Webhook Midtrans mengirimkan notifikasi status ke server FieldMax.
  6. Server memperbarui status Payment (PAID) dan Booking (CONFIRMED) secara otomatis.

Alur Operasional Renter & Cron

  1. Renter melihat pesanan masuk di Halaman Kelola Booking.
  2. Renter mengonfirmasi kehadiran penyewa di lokasi venue.
  3. Hourly Cron Job secara otomatis memeriksa seluruh booking terkonfirmasi yang melewati end_time.
  4. Cron job mengubah status booking menjadi COMPLETED.
  5. Analitik grafik pendapatan Renter diperbarui secara real-time.

Kesimpulan

1

Keberhasilan Rancang Bangun Platform Multi-Tenant

Platform FieldMax berhasil dirancang dan dibangun menggunakan Next.js (Frontend), Express.js (Backend), dan PostgreSQL (Prisma ORM). Platform mampu mengintegrasikan pencarian real-time, reservasi, pembayaran Midtrans Snap, dan manajemen Renter secara otomatis menggantikan proses manual.

2

Validasi Fungsionalitas via Black Box Testing

Hasil pengujian Black Box Testing membuktikan bahwa seluruh fungsi pada tiga aktor (User, Renter, Admin) berjalan lancar tanpa kesalahan (100% Passed), mampu mencegah jadwal ganda (double booking), serta menyediakan analitik omzet yang akurat.
